# Sidebar Redesign: Organization Spec (draft)

**Platforms:** Web and iOS. **Users:** about 40k, currently a flat note list plus search.

## 1. Key decision: 8 requests become 4 concepts

Several requests are the same idea under different names. Shipping all eight separately would give users eight overlapping ways to organize and a confusing sidebar.

| Request | Decision |
|---|---|
| Folders and nested folders | **Folders**, one feature, with nesting (max depth 4). |
| Tags and colored labels | **Tags**. Color is an optional property of a tag, with no separate "label" object. |
| Pinning and favorites | **Pin**. Pinned notes float to the top of their list and appear in a "Pinned" sidebar section. Folders and tags can be pinned too. There is no separate favorite flag. |
| Emoji icons | An optional `icon` field on notes and folders. It's cheap once the field exists. |
| Smart folders | **Saved searches** built on tags, folders and search. They ship last. |

## 2. Goals and non-goals

**Goals**
- Users can file a note in a folder and find it again without search.
- Existing users see no change until they opt in, and no note is moved or lost in migration.
- Behavior is identical on web and iOS, and it syncs.

**Non-goals for v1**
- Per-folder sharing or permissions.
- Notes in multiple folders (tags cover that need).
- Tag hierarchy.
- Auto-tagging rules.
- Custom sort rules for smart folders.

## 3. Sidebar layout

```
[Search]
All Notes (count)
Pinned           <- only shown if something is pinned
Folders          <- collapsible tree, with emoji icons
Tags             <- flat list, colored dot
Smart Folders    <- phase 3, hidden until used
Trash
```

- **Web:** a persistent, resizable, collapsible left panel.
- **iOS:** the sidebar is the root screen on iPhone and a column on iPad.
- Collapse state syncs across devices.

## 4. Requirements

**Folders**
- A note lives in exactly one folder, or in none.
- Create, rename, move and delete are supported.
- Max depth is 4, and a move that would exceed it is blocked with a message.
- Sibling names are unique, case-insensitively.
- Siblings sort alphabetically in v1.
- Selecting a folder shows its notes plus its descendants' notes.
- Deleting a folder asks whether to move its notes to the parent (the default) or send them to Trash. It never deletes notes silently.
- To move a note: drag-and-drop on web, a "Move to…" action on web and iOS, and long-press drag on iOS.

**Pin**
- Pin applies to notes, folders and tags.
- Pinned notes sort to the top of any list.
- The Pinned section has a soft cap of 20 items.

**Tags**
- A note can have many tags.
- Tag names are unique, case-insensitively.
- Color comes from a fixed palette of 8, accessible in light and dark. The name is always shown, so color is never the only signal.
- Tags are added through an autocomplete field in the editor.
- Rename and merge are global. Deleting a tag removes it from notes but never deletes the notes.
- Selecting multiple tags uses AND semantics.

**Emoji icons**
- One emoji per note or folder, from the native picker.
- It shows in the sidebar, list rows and note header.
- Validate that the value is a single grapheme.

**Smart folders (phase 3)**
- A smart folder is a saved query over text, tags, folder, pinned state and date ranges.
- It's created from "Save this search" in the existing search UI, so users already know the query language.
- Results are read-only.
- Queries reference tags and folders by ID, so renames don't break them.
- If a referenced tag or folder is deleted, the smart folder shows a "filter removed" notice instead of silently widening its results.

## 5. Data model

```
Folder      {id, user_id, parent_id?, name, icon?, pinned, timestamps, deleted_at}
Tag         {id, user_id, name, color?, pinned, timestamps}
NoteTag     {note_id, tag_id}
Note (add)  {folder_id?, icon?, pinned}
SmartFolder {id, user_id, name, icon?, query_json, pinned}
```

- `parent_id` exists from phase 1, so nesting needs no later migration.
- The server prevents folder cycles.
- The migration is additive and reversible. Existing notes get `folder_id = null` and `pinned = false`.
- Sync is last-writer-wins per field, and operations are idempotent.
- iOS must handle offline creates, moves and renames.
- If a folder is deleted on one device while a note is moved into it on another, the note falls back to the folder's parent.

## 6. Phasing

| Phase | Scope | Why |
|---|---|---|
| 1 | Sidebar shell, nested folders, pin, emoji icons | Most requested, and the foundation for the rest. Icons are nearly free once the fields exist. |
| 2 | Tags with color | A second axis for organizing, and it needs the phase 1 UI. |
| 3 | Smart folders | Only useful once tags and folders exist, and worth building after seeing real usage. |

Each phase ships behind a flag: internal users first, then about 5% of users, then everyone. Each phase must meet the metrics below before the next one starts.

## 7. Success metrics

- **Adoption:** the share of weekly active users who create at least one folder or tag within 30 days. Set the target after the phase 1 baseline.
- **Retrieval:** the share of note opens that come from sidebar navigation rather than search.
- **Guardrails:**
  - No rise in note-loss support tickets.
  - Sidebar load p95 under 300 ms with 5,000 notes and 200 folders and tags.
  - iOS crash rate unchanged.
- **Complexity check:** if fewer than 10% of adopters use nesting deeper than 2 after 60 days, simplify the nesting UI.

- **Web:** the tree is fully keyboard navigable, and moves work from a menu, not only by drag.
- **iOS:** VoiceOver labels include depth, expanded or collapsed state, and item count.
- **Test matrix:**
  - Offline moves.
  - Concurrent edits on web and iOS.
  - 5k+ notes.
  - Maximum nesting depth.
  - Emoji with skin tones and ZWJ sequences.
  - RTL names.

The main call for you is merging the requests into four concepts and phasing them. I'd settle questions 1 and 2 before design starts.
