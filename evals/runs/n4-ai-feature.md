# AI Writing Assistant: UX Design

**Core principle:** Eight features doesn't mean eight controls on screen. Most users want to select text, say what they want, and get a result. I'd organize the features into three tiers of exposure.

| Tier | Who | Features |
|---|---|---|
| **1. One click** | Everyone | Magic button, templates |
| **2. Light steering** | Most users | Tone, length |
| **3. Advanced** | Power users | Model, temperature, system prompt |
| **Persistent** | Everyone | History |

## Entry points

1. **Magic button** (✨) sits in the editor toolbar and appears in a floating menu when text is selected.
   - With a selection, it runs "Improve writing" on that text.
   - With no selection, it opens the assistant panel.
   - It does one predictable thing, with no settings required. A "magic" button that exposes a settings dialog defeats its purpose.
2. **Slash command** (`/ai`) in the document body opens an inline prompt for people who stay on the keyboard.
3. **Assistant panel** is a right-hand sidebar that docks next to the document and doesn't cover it. It holds everything else.

### Templates (8)
- Show them as a grid of cards with icon and name, not a dropdown. They're the main discovery surface.
- Picking one pre-fills the prompt scaffold, suggests a tone and length, and leaves everything editable.
- Selecting a template shouldn't auto-generate. People need a chance to add context.

### Tone selector (12 tones)
- Twelve is too many for a flat list. Use a searchable dropdown grouped into 3–4 categories, for example Professional (formal, confident, neutral), Friendly (casual, warm, enthusiastic), Creative (witty, poetic, dramatic), and Direct (concise, persuasive, urgent).
- Show a one-line example sentence on hover or focus so the names aren't ambiguous.
- Default to "Match my document", which is better than any fixed tone.

### Length slider
- Use 4–5 labeled snap stops (Shorter, Short, Medium, Long) rather than a continuous slider.
- Label the stops with approximate sizes ("~50 words") because abstract positions mean little.
- When refining existing text, offer "Shorter / Same / Longer" relative to the original.

### Advanced (collapsed by default)
- **Model picker (4 models):** Name the models by user-facing tradeoff ("Fast", "Balanced", "Most capable", "Creative"), with the technical model name in a tooltip. Default to Balanced. Show a cost or speed hint if usage is metered.
- **Temperature slider:** Relabel it "Predictable ↔ Creative". Only show the numeric value in a tooltip. Make it do double duty with the tone UI by disabling or hiding it when a model doesn't support it.
- **Custom system prompt:** Use a multiline field with a short helper ("Standing instructions applied to every request"), a character count, and a "Save as preset" option. Also let it be set at the workspace level so teams can enforce style guides.
- Add "Reset to defaults" and persist these settings per user.

### History panel
- It's a slide-over view inside the assistant panel, toggled from the header, not a permanent column.
- Each entry shows the prompt, a result preview, a timestamp, and the settings used (tone, length, model).
- Actions per entry are **Insert**, **Copy**, **Regenerate with same settings**, and **Restore settings**.
- Support search, and group by document with a "This document" filter by default.
- Add a clear delete control and a note about retention, since history stores user content.

## Result experience

This matters more than the controls.

- Stream the output into a **preview card** in the panel, not straight into the document.
- Actions are **Insert**, **Replace selection**, **Try again**, and **Refine** (a follow-up like "make it punchier").
- For edits on selected text, show an inline **diff** with accept/reject.
- Make every insert one undo step (Cmd+Z).
- Include thumbs up/down feedback and a **Stop** button during streaming.

## States to design

- **Empty:** Show templates and 2–3 example prompts.
- **Loading:** Stream the output and make it cancellable.
- **Error and rate limit:** Give a clear message and a Retry button that keeps the inputs.
- **Offline or model unavailable:** Fall back to the default model and say so.

# AI Writing Assistant: UX Design

## Core principle
Eight controls shown at once would make the feature feel like a settings page instead of a writing tool. Most users want to select text, say what they want, and get a result. So I'd split the controls into three tiers by how often people need them.

| Tier | Controls | Visibility |
|---|---|---|
| **1: Always** | Magic button, templates, tone | In the main surface |
| **2: Sometimes** | Length, history | One click away |
| **3: Rarely** | Model, temperature, system prompt | Behind "Advanced" |

## Layout

**Entry points**
- **Magic button** in the toolbar, with a `⌘J` shortcut. It also appears as a floating chip when text is selected.
- **Side panel** (right, collapsible) for the full assistant. It doesn't cover the document, so people can compare the draft and the suggestion.

**Magic button behavior**
- With text selected, it runs a smart default on the selection. The default is "Improve writing", using the user's last tone and length.
- With no selection, it opens the panel with a prompt input focused.
- The label should say what it does ("Improve" or "Rewrite"). A sparkle icon alone says nothing.

**Panel structure (top to bottom)**
1. **Templates**: a 2×4 grid of cards (for example Summarize, Expand, Fix grammar, Rewrite, Brainstorm, Outline, Translate, Reply). Picking one sets the task and can pre-fill sensible tone and length defaults.
2. **Tone**: a horizontally scrolling chip row, single-select. Twelve tones is too many for a dropdown to be scannable. Show the 5–6 most used, plus a "More" chip that expands the rest. Group them (Professional / Friendly / Persuasive / Creative) if they'll fit.
3. **Length**: a **segmented control** (Shorter / Same / Longer), with a slider only if PMs need fine control. Users think in relative terms for rewrites. For generation templates, switch to approximate targets ("~50 / 150 / 300 words").
4. **Generate** button, then the **result area** with Insert, Replace, Copy, Retry, and a diff toggle.
5. **Advanced** (collapsed accordion):
   - **Model picker**: name plus a plain-language hint ("Fast", "Balanced", "Most capable"), not raw model IDs.
   - **Temperature**: relabel as **Creativity** (Precise ↔ Creative). Hide the number, or show it only on hover.
   - **Custom instructions**: a textarea with a placeholder example and a "Save as default" option.
6. **History**: a tab or clock-icon drawer next to the panel title, not stacked under the controls.

## Key design decisions

- **Settings persist and are summarized.** When Advanced is collapsed, show a one-line summary ("Balanced · Creativity: medium · Custom instructions on"). Hidden settings that silently change output cause confusion.
- **Results are non-destructive.** Show suggestions inline as a diff, or in the panel with an explicit Replace. Undo (`⌘Z`) must revert an AI insertion in one step.
- **History stores the full recipe.** Each entry holds the input snippet, output, template, tone, length, and model. Clicking an entry restores the settings, not only the text. Allow search, and pin or delete entries.
- **Streaming output with a Stop button.** Keep the document editable while generating.
- **Smart defaults over blank state.** The first run should work with zero configuration.
- **Presets for power users.** Let people save a combination of tone, length, model, and instructions as a named preset. This is a better home for the custom system prompt than a bare text field.

## Things to push back on with the PMs

1. **Twelve tones and four models are many choices.** I'd suggest usage analytics to prune later, and an "auto" option for the model that picks based on the task.
2. **Temperature as a raw slider is a developer concept.** Rename it or fold it into a "Creativity" control. If most users never touch it, consider cutting it.
3. **The custom system prompt is a power-user and admin feature.** Consider also allowing workspace-level defaults set by admins, and note any safety or brand-voice constraints.
4. **The magic button's job needs defining.** Is it "improve selection", "continue writing", or a context-aware suggestion? If it means different things in different states, users won't trust it. I'd pick one primary behavior.
5. **Eight templates plus twelve tones can overlap.** "Make it friendly" is a tone, not a template. Keep templates for task types only.

## States to design
Empty (first run), loading or streaming, error or rate limit, offline, no selection, a very long selection (token limit warning), and a result that's identical to the input.

## Accessibility and mobile
- Full keyboard access: chips are arrow-navigable, and the panel is reachable through the command palette.
- Announce streaming results politely to screen readers.
- On mobile, the panel becomes a bottom sheet with templates and tone first, and Advanced behind a "More options" row.
