# School Pickup Coordinator: Product Plan

## What we're building
**Working name: CarpoolCrew.** It's a mobile app (iOS and Android) where parents in one class share pickup duty. It replaces the chaotic group chat of "Can anyone grab Maya today?" with a shared schedule, one-tap requests, and live status at pickup time.

**Core problem:** Pickup coordination is scattered across WhatsApp and text threads. Requests get buried, nobody knows who confirmed, and last-minute changes cause missed or doubled pickups.

**Primary users:** Parents and guardians of children in the same class. Secondary users are authorized alternates such as grandparents and nannies.

**Success metrics:**
- Percentage of requests confirmed within 30 minutes
- Missed or doubled pickups, which should be near zero
- Weekly active families per class

## Principles
1. **Safety first.** Children are only released to people on an approved list.
2. **Low friction.** Posting a request should take 3 taps or fewer.
3. **Privacy by default.** Only members of a class see anything. No public profiles, and no child locations beyond the pickup window.

## Features

### MVP
- **Class groups:** Join via invite code or link. A class admin (parent rep) approves members.
- **Family profiles:** Each family lists its children, guardians, and authorized pickup people, with a photo for each, so teachers can verify identity.
- **Pickup requests:** "I need someone to pick up [child] on [date/time]." Other parents can accept with one tap.
- **Offers:** "I'm driving Thursday and have 2 free seats."
- **Recurring swaps:** Weekly schedules, such as "Tuesdays are mine, Wednesdays are Priya's."
- **Calendar view:** Shows who is picking up whom, each day.
- **Push notifications:** New requests, acceptances, reminders 1 hour and 15 minutes before pickup, and changes.
- **Parent consent step:** The child's own parent must approve any pickup by another parent, either per event or as a standing approval.
- **Day-of status:** "On my way," "Arrived," and "Child picked up," visible to the child's parent.
- **In-app chat per request:** This keeps conversations short and attached to the event.

### Phase 2
- Pickup-code or QR verification at the school gate
- Reliability and fairness tracker ("who's owed a favor"), kept friendly rather than competitive
- School calendar sync, so early-release days and holidays are flagged automatically
- Backup requests: if nobody accepts within X hours, escalate to the whole class
- Multi-class and multi-child support
- Teacher/school view, read-only, for expected pickups

### Later
- Live ride ETA
- Shared costs or gas reimbursement
- Localization and accessibility extras

## Screens

**Onboarding**
1. Welcome and sign-up (phone or email, with verification)
2. Create or join a class (invite code)
3. Add family: children, guardians, authorized pickup people
4. Notification and location permissions

**Main tabs**
1. **Home / Today:** Today's pickups, any open requests, and status chips.
2. **Calendar:** Week and month views of the schedule, with a filter by child.
3. **Requests/Offers:** Feed of open items, with a "New" button.
4. **Class:** Member list, class info, invite, and admin tools.
5. **Profile/Settings:** Family, authorized list, notifications, privacy.

**Detail and flow screens**
- New Request (child, date/time, one-time or recurring, note)
- Request Detail (status, who accepted, chat, change or cancel)
- Offer Detail
- Consent prompt ("Approve [Name] picking up [Child]?")
- Day-of Pickup screen (status buttons, pickup code in Phase 2)
- Recurring Schedule editor
- Authorized People editor
- Admin: approve members, remove members, manage class
- Notification preferences

## Key flows
1. **Request:** Parent taps New, picks the child and time, and posts. Class gets a push. Another parent accepts. The child's parent gets a consent prompt if no standing approval exists. Both get reminders.
2. **Day of:** Pickup parent taps "On my way," then "Picked up." The child's parent sees each update.
3. **Fallback:** If nobody accepts by a set cutoff, the requester is alerted to arrange another option.

- **Backend:** Supabase or Firebase for auth, database, real-time updates, and push
- **Data model:** User, Family, Child, Class, Membership, AuthorizedPerson, PickupEvent (requester, child, time, status, assignee), Offer, Message, ConsentRecord

- **Repeat task, asking for cover:** 2 taps (tap the day, then "Need cover").

**Brilliant at:**
1. Today shows an unambiguous answer for each of your kids.
2. A cover request is a structured card: child, day, a "Can take" button. Classmates answer with one tap, and it never scrolls away.
3. Recurring plans mean nobody re-enters the routine each week.

**Depth, with where each piece lives:**

| Capability | Where it lives |
|---|---|
| Recurring weekly schedule | Automatic, set once |
| Reminders ("You're on pickup today, 2:45") | Default on, adjustable |
| Cover requests and offers | In context, on the day |
| Carpool groups (set sets of families) | One level down, under Class |
| Trusted adults (grandparent, nanny) | One level down, on the child's profile |
| Early-dismissal or holiday days | In context, on Week |
| Calendar export, notification controls, data export, delete account | Advanced, in Settings |

**Not now:**
- **In-app chat:** it recreates the group chat problem. A short note on a card covers it.
- **Live GPS or arrival tracking:** privacy risk, and it isn't the daily need.
- **Payments or cost splitting:** a separate product.
- **School admin portal and multi-class views:** build for one class first.
- **Ride-matching with strangers:** it breaks the trust model.

**States:**
- **First run:** the invite link lands directly on adding your child.
- **Empty:** a class with no plans says "Set your usual pickup days" with that one button.
- **Loading and offline:** show the last known plan, marked "as of 1:12pm", and queue edits.
- **Error:** "Couldn't send your request. We'll retry, nothing is lost."
- **Success:** the card shows "Maya's mum is covering Thursday" and notifies you.
- **Unanswered:** a request nobody has answered by a set time re-pings the class once, then prompts you to arrange backup yourself.

**Quality bar:**
- **Speed:** Today renders in under 1s from cache.
- **Notifications:** reliable, and the only way the app reaches people. Same-day changes must arrive within seconds.
- **Accessibility:** Dynamic Type, 44pt targets, and status never conveyed by color alone.
- **Privacy:** minimal child data (first name and initial, no photos, no location), and parents only.
- **Safety:** the app never replaces the school's authorized-pickup list. If someone not on the school's list is named, show "Check with the school".

**Technology:** Cross-platform mobile (React Native or Flutter) with a small managed backend: auth by invite, a relational store for classes, children, and pickup slots, and push notifications. Offline caching is the one hard requirement.

## Screens

Three tabs, with one primary action per screen:

1. **Join** (invite link, then add child, then set days). Onboarding is only this.
2. **Today** is the home screen. It has one card per child: who, what time, and any pending cover. The primary action is "Need cover" or "I can't make it".
3. **Week** is a grid of days by child, tap a day to change it. Dismissal exceptions show here.
4. **Class** lists families and carpool groups. Open requests and offers sit at the top.
5. **Request cover** is a bottom sheet with the day and child prefilled plus an optional note. Send is one button.
6. **Child profile** has trusted adults and school pickup notes.
7. **Settings** covers notifications, calendar sync, export, and delete account. It's reachable from a profile icon, labeled, not hidden.

3. **Is the school involved?** I assumed no. A school partnership changes safety and distribution.
